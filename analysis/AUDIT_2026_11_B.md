# Audit part 2, 13 Nov 2026: logs, trackers, speed

## Logs
| Problem | Effect | Fix |
|---|---|---|
| Rows dated by the run's clock, not the trading session | Monday 9 Nov's signals filed under the 10 Nov holiday (67 shocks, 33 catalysts, 17 breakouts, 34 agreements); the failed 9 Nov run also re-logged Friday's signals | Engine stamps each snapshot with `bar_date` and the Nifty move; every logger dates rows by it; a run with no new session records nothing |
| Splits and bonuses not handled | Returns across an action were nonsense: BUILDPRO -82.8% (really -14.0%), TDPOWERSYS -49.9% (+0.3%), CCAVENUE +702% | `utils/corp_actions.py` detects actions from consecutive snapshots (23 since Feb 2026) and every log computes returns on today's basis |
| `return_5d` / `return_21d` never filled | Empty on all 3,774 earnings-shock rows | Filled as rows reach that age; closed rows backfilled |
| Mood / breadth history | 21 weekend rows, 1 holiday row, up to 11 exact repeats | `scripts/repair_logs.py` (runs daily, idempotent); the dashboard no longer writes these files on page views |
| Rotation history | Two date formats; stale copy of Friday for 9 Nov | Normalised and repaired by the same script |
| Dashboard appended to the signal logs on every page view | Rows under the wrong date; three CSV rewrites per click | Dashboard only reads the logs |

## Trackers
| Problem | Effect | Fix |
|---|---|---|
| Positions, watchlist and price alerts saved only on the dashboard's disk | Lost on every redeploy; `positions.json` in the repo last changed 5 May; the EOD job never saw new ones | Same GitHub-backed store as RS alerts (alert-state branch), one operation per change |
| Unknown symbol | FEDERALBANK (NSE: FEDERALBNK) had no price for ten months | Near-identical symbols resolve automatically; unresolved ones raise an error and a Telegram line |
| Daily stop/target alert repeated every run | Same message each day while price stayed through the level | Sent once, then silent for 5 days |
| Price alerts only checked while the dashboard was open | No Telegram | EOD job checks them |
| Daily "NEW BUY SIGNAL" Telegram | Watchlist never expired, so alerts shrank to leftovers: 98% of the last 60 had RS below the engine's entry floor (median 2.3 vs 17) | Names leave the list when no longer a BUY; alerts need RS >= floor; relabelled "Scanner BUY" |
| Industry alerts stored twice | Every message sent twice | Duplicates collapsed and blocked |
| Email | "Connection unexpectedly closed" on every run | Retries over port 587 / STARTTLS |

## Speed (measured locally on the 12 Nov snapshot, Yahoo stubbed)
| | Before | After |
|---|---|---|
| Boot during the day (no snapshot for today's date) | full Yahoo download, 1,171 stocks x 14 months | newest snapshot, about 6 s first session, 2.5-3.5 s for later sessions |
| Trend Scanner, each click | 4.9 s | 1.8 s (one dropdown rebuilt 1,000 labels by filtering the table) |
| Sector Pulse, each click | 18.5 s (23 Yahoo calls) | 1.7 s (cached 12 h) |
| Live Desk / scanner charts | Nifty and holdings fetched from Yahoo on every click | cached 15-30 min |

Live prices are now opt-in (the Live Mode tick box); the sidebar states which session the prices are from.

## Not fixed
- The EOD workflow is scheduled for 3:45 pm IST but GitHub starts it around 11:20-11:45 pm IST.
- A stock whose action falls on a day with a missing snapshot is detected only if the factor is large.
- Closed log rows with distorted returns from before Feb 2026 (no snapshots) cannot be repaired.
