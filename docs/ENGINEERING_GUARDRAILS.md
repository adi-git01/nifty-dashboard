## 2. Quick Code-Review Red Flags (Check Before Every Merge)

When reviewing a diff or writing new code in this repository, stop and inspect carefully if any of these patterns appear:

- **`datetime.now()` / `date.today()` in EOD, logger, or market logic** → Should it be `bar_date`, NSE `DATE1`, or `IST`-localized with `holidays.csv` check?
- **`iloc[-4]`, `iloc[-N]`, `.diff(3)`, `.pct_change(N)` without date gaps** → Does a missing quarter or missing session shift the window? (`iloc[-(N + 1)]` for `N`-day returns; span filter for quarterly/annual fundamentals.)
- **`abs(x - y) <= tol` or single-sided `d <= max` thresholds** → Does a deeply negative value accidentally pass? Bound both ends.
- **`except Exception: pass`** in pipelines, daemons, or file loaders → Failure must either log/surface loudly or fail closed (especially on money locks, remote reads, and data persistence).
- **`background=True` or optimistic state updates** on orders/alerts → Orders must lock `SENDING` synchronously **before** HTTP calls; alerts must save `"sent"` **after** delivery succeeds.
- **`st.secrets` anywhere near `json.dump` / `open(..., "w")` / `st.toast` / `print`** → Separate local config reads from secret lookups and redact tokens before formatting errors.
- **Hardcoded paths (`data/*.csv.gz`, unvalidated `f"{ticker}.json"`)** → Use `utils/fund_paths.resolve(...)` and `_safe_ticker_filename` + `os.path.realpath` containment.
- **`<=`/`>=` checks against raw symbol strings** → Verify `.NS` / `.BO` normalization (`clean_symbol`, `normalize_ticker`, `f"{base}.NS" in eq_symbols()`).
- **Destructive rewrites from a subset** (`to_csv` / `to_parquet` inside loops over current snapshot dates or partial ticker lists) → Verify historical records outside the active window are merged/preserved, not dropped.
